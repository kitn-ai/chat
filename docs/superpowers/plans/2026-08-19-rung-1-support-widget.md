## What rung 1 is

The smallest real application: a docked support chat widget — floating launcher, panel with
`<kai-chat>`, submit, streaming replies. **No conversation history.** Vanilla TS + Vite.
Mock responder for the body of the work; validated once against a real provider (OpenRouter,
owner's key) at the end. Done when: runs against a real provider, checked in, builds in CI.

## Rulings

- **Home: `examples/apps/support-widget/`** — a new corpus directory for the ladder's apps, NOT
  `examples/starters/` (which means "one minimal mock-only starter per framework"; five ladder
  apps would silently change that meaning). `verify-starters.mjs` is extended to enumerate
  `examples/apps/` with the same derived-roster, hard-fail semantics. The apps corpus is the
  consolidated home the spec requires; it absorbs overlapping artifacts as rungs land.
- **`examples/demos/widget/` is REPLACED, not kept alongside** — it is the same docked-widget
  shape as rung 1, CDN-pinned, hand-rolled canned replies, outside every CI guard. Deleted in
  this rung; references updated to point at the new app. `demos/composable/` stays (it is a
  roster showcase, not an app).
- **Key handling copies the openrouter-spike pattern exactly**: unprefixed `OPENROUTER_API_KEY`
  (never `VITE_`-prefixed, so Vite cannot inline it), read only inside a dev-server middleware
  proxy. The widget fetches `/api/chat` in both modes; with no key present the endpoint serves
  `createMockResponder()` frames, with a key it proxies OpenRouter. Same client code path either
  way — the mock/real seam is server-side, so the wire path under test is identical.
- **CI never talks to a live model** (spec risk section). CI runs build + typecheck via the
  extended `verify:starters`. The real-provider run is a local, one-time acceptance step.
- **Streaming parses through `@kitn.ai/ui/wire`'s `readOpenAIStream`** — never a hand-rolled SSE
  reader (CLAUDE.md contract).
- Docs/catalog pointer updates (`apps/docs/.../examples/support-widget.mdx` corpus pointer, the
  `support-widget` archetype's `docsSlug`, `surfaces.ts` corpus) are included ONLY as pointer
  updates; reconciling docs prose is the planned docs pass, not this rung.
