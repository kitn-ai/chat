# Per-element CSS floor: measurement + decision memo (WS1 item 10)

Date: 2026-08-25. Charter: WS1 surface audit item 10
(`docs/superpowers/research/2026-08-25-css-floor-measurement.md` is this file; the audit is
`2026-08-25-ws1-surface-audit.md` section D; the original plan is
`docs/research/footprint-reduction-plan.md` Lever 2 / Phase 3). Read-only on source; this file is
the only write. Every number below was measured this run — commands inline so any figure can be
re-derived. All gzip figures are `gzip -9` (zlib level 9 for the in-process ones).

**Verdict up front: status quo — close item 10.** The floor is real (~19.9 KB gz, half of a
leaf-element page) but the maximum win is ~12 KB gz on a page that already costs only 40 KB gz
total, the JS floor beside it is the same size and untouched by any CSS split, and the split
carries a silent-breakage risk class this kit has already been bitten by twice. Numbers, then the
reasoning.

## 1. What the shared CSS actually costs

### The sheet itself

`src/elements/compiled.css` (generated by `build:css` = Tailwind v4 CLI over
`src/elements/styles.css`, then `postprocess-element-css.mjs`):

| | raw | gzip |
|---|---|---|
| `compiled.css` | 129,134 B | **19,957 B (~19.5 KB)** |

The plan doc's "17 KB gz" is stale, as its own stale-numbers rule predicted: the sheet grew with
the 33 elements added since 2026-06-20. (`wc -c`; `gzip -9 -c | wc -c`.)

### How it reaches a per-element consumer — shared, embedded once, never duplicated

- `src/elements/css.ts` imports `compiled.css?inline` as a string; `define.tsx:15–21` builds
  **one** `CSSStyleSheet` via `replaceSync` and adopts it into every element's shadow root
  (`define.tsx:493–494`; `<style>` fallback per root at :501 only where constructable sheets
  don't exist).
- In `dist/elements/` the string is embedded **once**, inside the shared chunk
  `chunks/define-C2X3b56G.js` (164,577 raw / 33,934 gz; the embedded sheet accounts for
  19,866 gz of that, the chunk's JS remainder ≈ 13.2 KB gz). Every element entry imports that
  chunk. So: shared chunk, not inlined per element, not duplicated per element file — over the
  wire the sheet is paid exactly once no matter how many elements a page uses.
- Beware the decoy: `chunks/css-*.js` is the Shiki **CSS-language grammar**, not the stylesheet.
- Element chunks have **zero bare imports** — Solid is bundled — so dist bytes are what a
  consumer ships; a bundler only re-concatenates them.

### What a minimal one-element page pays

Static+dynamic chunk closure of each dist entry (sum of per-file gz):

| Entry | files | raw | gz total |
|---|---|---|---|
| `elements/badge.js` | 5 | 194,896 | **44.0 KB** |
| `elements/kbd.js` | 4 | 195,385 | 44.1 KB |
| `elements/button.js` | 22 | 212,544 | 53.0 KB |
| `elements/chat.js` (for scale; includes lazy Shiki chunks) | 86 | 1,478,927 | 324.6 KB |

Honest consumer measurement (esbuild `--bundle --minify` over the dist entry, single output file,
scratchpad throwaway):

| Bundle | raw | gz | CSS share |
|---|---|---|---|
| badge only | 186,962 | **40.1 KB** | 19.9 KB gz = **50%** |
| badge + kbd + button | 202,600 | **47.6 KB** | 19.9 KB gz, paid once = 42% |

Badge's own facade + component chunks are 1,034 B raw (~0.7 KB gz). So the leaf-element floor
decomposes as: **~19.9 KB gz CSS + ~20 KB gz JS** (define-chunk JS ≈ 13.2 + `cn` chunk
(tailwind-merge + helpers) ≈ 9.0 + entry slivers), and the element itself is noise.

## 2. What a per-element CSS split would entail, with measured ceilings

How the sheet is produced: one Tailwind v4 pass, `@source "../"` — the whole `src/` tree — plus
`tw-animate-css`, `theme.css`, and the typography plugin; then the postprocess script rewrites
Tailwind's `@supports` fallback gate so `--tw-*` properties work inside shadow roots (a
zero-match-hard-fail guard). Utilities are **not** attributed per element anywhere; attribution
would have to be derived from each facade's transitive module graph.

Experiment (scratchpad, same styles.css with `source(none)` + explicit `@source` lines):

| Variant | raw | gz |
|---|---|---|
| Badge-scoped sheet (the facade's 15-file transitive import graph as sources) | 50,232 | **8.0 KB** |
| Irreducible core (`source(none)`: preflight + theme + base layer, zero utilities) | 19,636 | **4.1 KB** |

Spot-checked that the scoped sheet contains badge's own utilities (`inline-flex`,
`rounded-full`). So the realistic options:

- **(a) Full per-element extraction** — one Tailwind pass per element over its module graph,
  per-element sheet adopted alongside nothing shared. Best case for badge: 19.9 → 8.0 KB gz,
  page 40.1 → ~28 KB gz (−30%). Cost: a graph-derivation script + 83 Tailwind passes in
  `build:css` + the postprocess ungate applied per sheet + `define.tsx` plumbing to adopt the
  right sheet per tag. **Regression built in:** a multi-element page pays the overlapping
  utilities once per element's sheet — the three-element page above could end up *heavier* than
  today's 47.6 KB. Effort M–L.
- **(b) Shared core + per-element delta** — the 4.1 KB core adopted everywhere plus a per-element
  delta sheet (element-scoped minus core; badge delta ≈ 4 KB gz). Same ceiling as (a) for a leaf
  (~28 KB gz page), softens but does not remove the multi-element duplication (deltas still
  overlap pairwise). Adds a set-subtraction step on top of everything in (a). Effort L.
- **(c) Status quo** — one sheet, one shared chunk, paid once. Effort 0.

Both (a) and (b) share a correctness-risk class independent of effort: Tailwind can only scan
literals, so any class reaching an element through a path outside its statically-derived graph —
a `cn()` argument built dynamically, a class passed as a prop across a graph boundary, a shared
helper the graph walk misses — compiles to **nothing, silently**, per element. That is exactly
the failure shape `styles.css` documents for the animate-in utilities ("silently dead") and the
postprocess script documents for focus rings (invisible focus indicators shipped). Today's
whole-tree scan is what makes that class of bug impossible; a per-element split re-opens it 83
times and would demand a per-element computed-style guard to close again.

## 3. Decision

**Recommendation: (c) status quo. Close item 10.**

- **What the split buys at its ceiling:** ~12 KB gz on a leaf page, taking it from 40 → 28 KB gz.
  40 KB gz for a fully themed, focus-managed, animated custom element with its framework runtime
  bundled is already smaller than a bare React+ReactDOM pair; nobody's decision to adopt a
  `kai-badge` flips on 12 KB.
- **CSS is not the lone floor.** The JS floor beside it (~20 KB gz of define/cn/Solid runtime) is
  the same order and untouched by any CSS work — halving the CSS still leaves a ~28 KB leaf page,
  a 30% win, not a 5× one. The audit's framing "for leaf elements the floor IS the bundle" is
  right, but the floor is half CSS, half JS, and only the riskier half was on the table.
- **The multi-element case regresses.** WS1's thesis is *composing several* small elements; the
  shared sheet is optimal for exactly that (19.9 KB once, badge+kbd+button = 47.6 KB gz), while
  per-element sheets pay overlap per element. The split optimizes the one-element demo at the
  expense of the composition story WS1 actually promotes.
- **The risk profile is the kit's known worst one:** silently-missing styles, per element,
  guarded today by construction (whole-tree scan) and after a split only by 83 new visual guards.

Re-open triggers, so this stays closed on evidence rather than forever: (1) the sheet crossing
~35 KB gz (it grew 17→19.9 over two months of heavy element growth — linear, not alarming);
(2) a marketed CDN/script-tag leaf-element front door where a 28-vs-40 first-paint number becomes
sales copy; (3) Tailwind or the build gaining first-class per-graph attribution that removes the
silent-miss class. If re-opened, option (b)'s core sheet (4.1 KB gz measured) is the starting
point, and the badge-graph experiment in the scratchpad (`twexp/`) is the prototype to lift.

Bookkeeping for the audit: section D's "17 KB gz" figure should read ~19.9 KB gz (0.26.0), and
its "that is now the dominant cost" becomes "half the floor, tied with the JS runtime floor".
