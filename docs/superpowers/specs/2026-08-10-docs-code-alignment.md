# apps/docs vs the shipped API — mechanical alignment report

Generated by `apps/docs/scripts/docs-alignment/` at commit `3ff3543`, against `@kitn.ai/ui` 0.19.0 as built into `packages/ui/dist`.

**This is a snapshot.** Every name checked here is read at run time from the built `dist/*.d.ts` and from `src/elements/element-meta.json` — nothing is baked into the harness — so the numbers move when the API moves. Re-run rather than trusting the counts below once the surface changes.

## How this was found

Doc snippets are fragments: they call the reader's own functions, omit imports, and import packages this repo does not install. Compiling them naively produces a wall of false positives and the check gets switched off. The line this harness holds instead:

> A snippet referencing the READER's code must not fail. A snippet that imports or uses a **kit** symbol that does not exist, or passes a prop a kit component does not accept, must fail.

Four mechanisms do that:

1. **Unknowns are resolved by the compiler, not guessed.** Compile, collect every `Cannot find name 'X'`, declare those as `any`, recompile until it settles. The compiler's own scope analysis decides what is undeclared. Stubs sit on one prepended line inside a module, so they are scoped to their own snippet and every reported line number is off by exactly one, which is subtracted back out. When the unknown name IS a kit export and the snippet already imports from the kit, the real import is injected instead of an `any` stub, so a fragment that omits an import still gets its props checked.
2. **Kit modules are never shimmed.** Third-party specifiers that do not resolve become shorthand ambient modules (`any`). `@kitn.ai/ui` and its subpaths are excluded by a hard guard — an unresolved kit entry point or a missing exported member always fails.
3. **Findings are split by ORIGIN, not by error code.** For each diagnostic the checker is asked where the offending type was *declared*; anything declared under `packages/ui` is kit drift. That is what separates "unknown prop on a kit component" from "unknown prop on the reader's own object", and it lets untyped `js` blocks be checked for kit drift only.
4. **Fragments are interpreted, not rejected.** A block that does not parse as a module is retried as a type shape, a class member, and a bare value; the first interpretation that parses is used. Genuinely malformed code still fails, which the self-test proves.

The `kai-*` contract is checked **structurally** against `element-meta.json` rather than by tsc, because the kit's shipped React JSX augmentation types every element as `{ [attr: string]: unknown }` and cannot reject a misspelled attribute — and because 134 of the 355 blocks are plain `html` that tsc never sees.

Two deliberate exemptions, both self-tested so they cannot silently swallow real findings: snippets the docs explicitly mark as counter-examples (`<!-- Fails — an array can't be an HTML attribute -->`), and JSX placeholder children (`{/* your components */}`).

## Honest assessment: how much of the drift is mechanically detectable

Roughly **a third**, and it is the cheap third.

What a machine settles conclusively: does this name exist, does this prop exist, does this element exist, does this event exist, does this snippet compile against the shipped types, is this local type compatible with the kit's. Every finding above is one of those, and each is either true or false with no judgement involved. That is the whole first two sections of this report.

What it cannot settle, and where the rest of the drift lives:

- **Whether a snippet that compiles actually works.** Nothing here is executed. The parts-flattening bug in `guides/frameworks/solid.mdx` compiled cleanly for as long as it existed, and was only caught because the page happened to re-declare a type the kit exports. A page that flattens `parts` without re-declaring anything would still be invisible.
- **Whether prose is true.** Names are checked; claims are not. The 47 items flagged for human review are the ones worth checking, and the harness deliberately refuses to guess at any of them.
- **Whether the recommended approach is still the recommended approach.** A page can be entirely correct and entirely outdated.
- **Whether an example is good.** Ordering, completeness, error handling, whether the snippet teaches the pattern the kit wants taught.

The honest framing: this harness makes the mechanical third *free and repeatable*, and it makes the other two thirds **visible and bounded** — 47 extracted claims and two reverse-coverage lists are a finite human task, where "read 120 pages and check everything" is not. It is a filter, not a verdict.

One more caveat worth stating plainly: this harness has already been wrong. Its first full run reported 73 high-confidence findings; 64 of those were its own bugs (Vue's `.prop` modifier, Svelte's `{messages}` shorthand, a CSS custom property parsed as an element, prose inside comments, the docs' own counter-examples). Each was found by checking a sample of findings against the source by hand. The number below is what survived that; it is not proof that nothing else is wrong with it.

## What this harness does NOT cover

Stated plainly, because a coverage claim nobody bounded is how a check ends up proving nothing.

- **Prose meaning.** Only names are checked, not sentences. "`ChatContainer` owns the scroll" is unverifiable here; the harness only knows `ChatContainer` exists.
- **Runtime behaviour.** No snippet is executed and no page is rendered. A snippet that compiles and renders nothing looks identical to a correct one.
- **Visual/UX claims.** Screenshots, layout, theming results.
- **Untyped JS depth.** `js` and inline `<script>` blocks are checked for kit-API drift only. A logic bug in an untyped snippet is invisible.
- **Non-code fences.** 28 block(s) in languages with no checker here (bash, json, jsonc, python, sh, toml).
- **Uninstalled third-party packages.** 15 specifier(s) resolve to `any` by design, so misuse of them is not caught: `@ai-sdk/openai`, `@angular/core`, `@angular/platform-browser`, `@langchain/core/tools`, `@langchain/langgraph/prebuilt`, `@langchain/openai`, `@mastra/client-js`, `@tanstack/react-router`, `@vitejs/plugin-vue`, `ai`, `https://cdn.jsdelivr.net/npm/@kitn.ai/ui/dist/elements/autoloader.js`, `https://cdn.jsdelivr.net/npm/@kitn.ai/ui/dist/kai.es.js`, `openai`, `vite`, `zod`.
- **Angular / Vue / Svelte templates.** Only the `<script>` half is compiled; the template half gets the same structural `kai-*` checks as HTML.

### CI status: NOT wired in yet

Deliberately. Cost is not the reason — the whole run is about 10s and needs no network, which is well inside what the required job already spends on `verify:scaffold`. Two things have to be true first:

1. **The tree has to be green.** A gate added while it reports findings is a gate that is red on arrival, and a red-on-arrival gate gets bypassed rather than fixed. High and medium are currently at 0 and 0, so this precondition is met as of this run — re-check it rather than trusting this sentence.
2. **It needs one more adversarial pass.** The first full run reported 73 high-confidence findings and 64 were the harness's own bugs. That ratio came down by hand-checking findings against the source. Every finding since has been verified by reading the page, and the severity rules are now probed directly — but the harness has not yet survived anyone deliberately trying to make it lie.

Suggested sequencing: land it as a non-blocking job that posts the report, watch it for a few PRs, then promote it to required once the high count has stayed at zero on its own.

The self-test runs first, every time. It compiles six snippets that MUST produce a kit finding (unknown entry point, unknown export, bogus prop on a kit component, wrong argument type, wrong arity, removed wire API), seven structural probes that MUST report (unknown element, unknown prop, non-scalar-as-attribute, unknown event, unknown part, stale `<Example tag>`, stale `<Example config>` key), six severity probes that pin what GATES (widening gates in a `ts` block and is advisory in an untyped one, while shape drift — a missing or misspelled property against a kit type — gates in an untyped block too), a shadow probe that must go from clean to broken when the real type is substituted, and five probes that MUST stay silent (reader-owned undeclared names, omitted imports, uninstalled third-party imports, valid markup, non-scalar props bound as JSX expressions). If any probe misbehaves the run aborts before touching the docs, because a green result would be meaningless.
